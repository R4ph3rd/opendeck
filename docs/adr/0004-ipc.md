# ADR 0004: IPC between Rust and the UI

- Status: accepted
- Date: 2026-10-29
- Deciders: architect

## Context

The UI (React, `ui/`) talks to Rust through Tauri 2. We want one source of truth for every IPC type, generated TypeScript, binary transfer for large numeric data, and a CI check that the generated file is current.

## Decision

### Commands and events

- Commands are `#[tauri::command] #[specta::specta]` functions in `src-tauri/src/`, registered in `specta_builder()`. Each forwards to `opendeck_app_core`; no logic in the shell.
- Events are types deriving `tauri_specta::Event` with an explicit kebab-case `event_name` (for example `engine-telemetry`).
- Command and event names are `snake_case` in Rust and `camelCase` accessors in TS (`commands.appInfo()`); the wire name stays `app_info`.
- Fallible commands return `Result<T, CommandError>`; the binding returns `{ status: "ok", data } | { status: "error", error }`.
- The planned list is `docs/ipc.md`. Adding a command there first is part of the contract.

### Types

- DTOs live in `crates/contracts` and derive `specta::Type` behind the `specta` feature; shell-only DTOs (`AppInfo`, `CommandError`) live in `src-tauri`.
- Field names on the wire are serde defaults (`snake_case`). Enums are `snake_case` strings or tagged objects as declared in contracts.
- `u64`/`i64` (row ids, frame counts) are exported as `number` via `dangerously_cast_bigints_to_number`. Values stay below 2^53 (2^53 frames at 48 kHz is about 5900 years; SQLite row ids are sequential).
- `f32`/`f64` are typed `number | null` by specta, because serde writes non-finite floats as `null`. Rust never sends non-finite values; the UI treats `null` as missing.
- Serialize and deserialize shapes are identical (`disable_serde_phases`), so each type has one TS alias.

### Bindings generation

- Output: `ui/src/ipc/bindings.ts`, generated, never edited, excluded from ESLint.
- Regenerate: `cargo run -p opendeck-desktop --bin export-bindings` (no window, works headless).
- Check: the test `bindings_are_up_to_date` in `src-tauri` fails if the committed file differs. CI also runs the exporter and `git diff --exit-code ui/src/ipc/bindings.ts`.
- `tauri-specta = "=2.0.0-rc.26"`, `specta = "=2.0.0-rc.26"`, `specta-typescript = "=0.0.13"` are pinned exactly and bumped deliberately (ADR 0001).

### Binary payloads (waveform peaks, later spectra)

JSON arrays of numbers are not used for bulk data. Peaks are fetched by a dedicated command returning `tauri::ipc::Response` with the raw peak blob (format `contracts::peaks`, magic `ODPK`, version 1). In JS the result is an `ArrayBuffer`, decoded with a `DataView` per the documented layout.

tauri-specta cannot type `tauri::ipc::Response`, so raw-byte commands:

1. are registered in the same invoke handler through a small dispatcher that routes their names to `tauri::generate_handler![...]` and everything else to the specta handler;
2. have their TS wrappers in one hand-written module, `ui/src/ipc/raw.ts`, which only calls `invoke<ArrayBuffer>` and decodes; it is reviewed as part of the contract.

Planned raw commands: `get_track_peaks(track_id, level)` (milestone 2). Live meters stay in the JSON telemetry event: it is a few dozen numbers per frame.

### Telemetry

`engine-telemetry` carries one `EngineTelemetry` snapshot, emitted by the control thread at ~60 Hz (ADR 0003). The UI writes it into a non-React store; components read it from `requestAnimationFrame`, never through React state per message.

## Consequences

- A Rust type change shows up as a TS compile error in the UI.
- Raw commands are the one place where TS types are hand-written; keep that module small.
- Bumping the specta RCs may change generated output; that diff is reviewed like code.
